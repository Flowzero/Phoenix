# Тестирование PHOENIX

Набор проверяет реализованный код проекта: onboarding, разрешения, состояние Bluetooth и геолокации, BLE-сканирование, хранение признака первого запуска и интерфейс. Это не подтверждение готовности обмена сообщениями между телефонами.

## Запуск на компьютере

Из корня проекта в PowerShell, с установленными JDK и Android SDK:

```powershell
$env:JAVA_HOME = 'C:\Users\bankai\.jdks\jbr-21.0.11'
.\gradlew.bat :app:testDebugUnitTest --console=plain
```

Путь к JDK выше соответствует проверенному окружению; на другом компьютере следует указать свой JDK. Достаточно изменить переменную текущего окна PowerShell, глобальные настройки Java менять не требуется.

Полный запуск включает модульные, локальные интеграционные, Compose UI и регрессионные тесты. Сейчас команда завершается с ошибкой из-за шести воспроизводимых дефектов приложения, а не из-за ошибки сборки тестов. Они не отключены и не помечены как ожидаемо успешные: описание — в [KNOWN_DEFECTS.md](KNOWN_DEFECTS.md).

JaCoCo автоматически формирует покрытие даже после падения тестов:

- Результаты проверок: `app/build/reports/tests/testDebugUnitTest/index.html`.
- Покрытие: `app/build/reports/jacoco/jacocoDebugReport/html/index.html`.
- Машиночитаемое покрытие: `app/build/reports/jacoco/jacocoDebugReport/jacocoDebugReport.xml`.

Запуск отдельного класса, например:

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests 'com.example.scratched.integration.*' --console=plain
.\gradlew.bat :app:testDebugUnitTest --tests 'com.example.scratched.regressions.*' --console=plain
```

Фильтр перезаписывает результаты и покрытие данными выбранных тестов. Для итогового отчёта нужен повторный запуск **без** `--tests`. Чтобы принудительно повторить уже выполненные задачи, можно добавить `--rerun-tasks`.

## Что проверяется

| Область | Автоматические проверки | Граница проверки |
| --- | --- | --- |
| OnboardingFlowCoordinator | Приоритет шагов, первый/повторный запуск, отказ/выдача разрешений, включение Bluetooth/геолокации, необязательные уведомления, завершение и сброс | Включает SDK 29, 33 и 35; реальные системные диалоги здесь не открываются |
| PermissionsManager | Наборы разрешений до/после Android 12 и 13, обязательные/необязательные разрешения, отозванные разрешения | Через Robolectric либо моделирование Android-границы |
| Bluetooth/Location adapters и managers | Доступность и состояние сервисов, ошибки доступа, запрос включения, мониторинг, регистрация/снятие receiver | Android-службы симулированы; доставка broadcast от настоящей Bluetooth-службы требует устройства |
| OnboardingPrefsRepository | Чтение/сохранение/сброс completion, новый экземпляр репозитория после завершения | Настоящий SharedPreferences в Robolectric |
| MainViewModel и factory | Создание, жизненный цикл, преобразование событий, разрешения, статусы сканирования, объединение устройств по адресу, обновление имени/RSSI/счётчиков, очистка новой сессии | Модульные тесты используют зависимости-заглушки; интеграционные — реальные связанные компоненты |
| BluetoothGattClientManager | Параметры запуска, Stop, повторный Start, задержка 4999/5000 мс, повторная проверка разрешений, исключения Android API, разбор рекламных данных | Реальный менеджер; только радио API и callback заменены. Это не испытание физического BLE |
| Интеграция onboarding | ViewModel → coordinator → реальные permissions/managers/SharedPreferences; обратный поток событий; broadcast; восстановление после выдачи разрешений | Адаптеры Bluetooth/геолокации заменены; SDK 29, 33, 35 |
| Интеграция сканирования | Реальный GATT manager → SharedFlow → ViewModel → экранное состояние; Start/Stop, дедупликация, новая сессия | Радио API заменены, остальные компоненты реальные |
| MainActivity | Настоящие Activity, Compose, ViewModel, factory, coordinator и storage; переходы, системные intents и результаты Activity Result API, возврат из настроек, отзыв разрешения, Stop при уничтожении | Robolectric, SDK 33; системные службы и ответы пользователя симулированы |
| Компоненты Compose | Восемь экранов onboarding, действия кнопок, предупреждения, статусы, данные устройств и отсутствующие метаданные | Одинаковые сценарии доступны локально и на Android-устройстве; пиксельное сравнение/визуальная приёмка не выполнялись |
| Найденные дефекты | Шесть активных регрессий с проверкой правильного ожидаемого поведения | Сейчас падают до исправления приложения |

## Где находятся тесты

- `app/src/test/java/com/example/scratched/`: локальные модульные тесты.
- `app/src/test/java/com/example/scratched/integration/`: интеграция реальных компонентов.
- `app/src/test/java/com/example/scratched/regressions/`: воспроизведения найденных ошибок.
- `app/src/test/java/com/example/scratched/support/`: управление временем/диспетчером, фейки адаптеров, моделирование радио API.
- `app/src/sharedTest/java/com/example/scratched/ui/`: общие проверки Compose. `sourceSets` подключает их к обоим видам запуска.
- `app/src/test/.../ui/`: локальные обёртки с Robolectric.
- `app/src/androidTest/.../ui/`: обёртки для Android-устройства/эмулятора.

В интеграционных тестах не подменяется одновременно вся проверяемая цепочка. Заглушки отделяют только Android/радио-границы либо компоненты, не относящиеся к конкретному сценарию. Бесконечные сборщики Flow привязаны к ViewModelStore или `backgroundScope` и освобождаются после теста.

## Запуск на устройстве

Подключить тестовый Android-телефон с разрешённой отладкой либо запустить настроенный эмулятор. Команда ниже устанавливает приложение и тестовый APK на выбранное устройство:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest --console=plain
```

Проверить сборку тестового APK без установки:

```powershell
.\gradlew.bat :app:assembleDebugAndroidTest --console=plain
```

Общие UI-сценарии проверяют компоненты экранов и callbacks. Они **не** проверяют фактическое разрешение системных диалогов, устойчивость радио и обмен между двумя аппаратами. Для этого нужны отдельные аппаратные сценарии, а для передачи данных — сначала реализация протокола.

## Изменения приложения ради тестируемости

В `BluetoothGattClientManager` добавлен необязательный источник времени. По умолчанию используется тот же `System.currentTimeMillis`, что и раньше. В тестах он связан с виртуальным временем корутин: задержки проверяются точно, без реального ожидания пяти секунд. Остальные изменения — тесты и конфигурация их запуска/покрытия; найденные дефекты приложения не исправлялись.

## Что ещё нельзя считать проверенным

- `BluetoothGattServerManager.startAdvertising()` пока только строит AdvertiseData: advertising/GATT server не запускается.
- `BluetoothConnectionManager` и `DeviceIDManager` — заготовки без реализованной логики.
- Подключение к peer, HELLO/DATA/ACK, сообщения, доставка/повторные попытки, background service, relay и шифрование в текущем коде не реализованы. Проверки не заменяют отсутствующую реализацию.
- На физических устройствах не проверялись обнаружение и совместимость разных производителей, broadcast от системной Bluetooth-службы, реальная смена разрешений, отключение радио во время сканирования, фон, экран/энергосбережение, восстановление соединения, потери пакетов, дальность и нагрузка.
- Не выполнялись визуальная приёмка, полный аудит безопасности и полная матрица устройств/версий Android.

`meshMVP/README.md` исключает relay, store-and-forward и криптографический обмен ключами из MVP и предусматривает фоновый сервис. Это отличается от ранее составленного предварительного плана приёмки команды. Результаты этих тестов не означают соответствие тому плану.
