# Разделение BLE discovery и сохранение отладочного экрана

Изменение продолжает PR #2. Реализован рефакторинг обнаружения устройств,
а не GATT-соединения или обмен сообщениями.

## Ответственность компонентов

| Компонент | Ответственность |
| --- | --- |
| `BleDiscovery` | Контракт запуска, остановки, проверки готовности и наблюдения за сессией |
| `BluetoothGattClientManager` | Связывает backend, контроллер, кэш и единый snapshot сессии |
| `ScanSessionController` | Поколения сессий, монотонный интервал запусков, отмена таймера, ошибки и закрытие |
| `AndroidBleScanner` | Android startScan/stopScan, фильтр, преобразование ScanResult в нейтральное наблюдение |
| `AndroidScanReadiness` | Проверяет поддержку BLE, permissions, Bluetooth и необходимость location |
| `DiscoveryDeviceStore` | Объединяет наблюдения по адресу, сохраняет счётчики и ограничивает кэш |
| `DiscoveryUiMapper` | Преобразует нейтральные данные в существующие отладочные UI-модели |
| `CoroutineScanScheduler` | Владеет только задачами отложенного запуска, отменяется при close |
| `MainViewModelFactory` | Создаёт и соединяет реализации |

Транспорт не импортирует BleDeviceUiModel, MainScreenUiState или Compose.
ViewModel зависит от BleDiscovery, не от конкретного Android backend.
Название BluetoothGattClientManager сохранено для связи с существующим кодом;
этот класс пока координирует только discovery и не создаёт BluetoothGatt.

## Что исправлено

- Результаты больше не передаются через SharedFlow/tryEmit, где наблюдения могли
  теряться до подписки или при переполнении буфера. Сервис сохраняет их и публикует
  один StateFlow snapshot со статусом, списком и временем начала. Подписчик может
  пропускать промежуточные snapshots, но получает последний накопленный результат.
- Проверка поколения сессии и запись наблюдения выполняются под одним lock:
  остановка не может вклиниться между проверкой callback и изменением списка.
- Backend может прислать callback до возврата из start(). При синхронной ошибке
  или закрытии вернувшийся handle также освобождается.
- Stop и close безопасны при повторном вызове. Ошибка cleanup не оставляет
  сессию активной; поздние callbacks отбрасываются. Первичная ошибка Android
  сохраняется, даже если stopScan тоже завершился ошибкой.
- Уход экрана в фон не затирает уже полученную ошибку состоянием STOPPED.
- Readiness проверяется при запросе и перед фактическим отложенным стартом.
  Отклонённый preflight не расходует программный лимит радио-стартов.
- SCAN и CONNECT на Android 12+ достаточны для данного пути discovery;
  ADVERTISE не требуется сканеру. CONNECT используется для чтения состояния адаптера.
  Общий onboarding по-прежнему готовит разрешения для будущих обеих ролей.
- Метаданные и имя обновляются в одном месте. Пустое имя не стирает ранее известное.
  Входные коллекции копируются; UI получает собственные ByteArray для manufacturer data.
- Кэш ограничен 256 адресами; при переполнении удаляется устройство, которое
  дольше всех не наблюдалось. Это кэш текущей сессии, не реестр peer identity.
  Адреса могут меняться. Stop оставляет список для анализа, новый старт очищает его.

## Отладочный экран

Сохранены кнопки запуска/остановки, статусы, список и подробности advertisements.
Добавлен переключатель `Show all BLE devices`:

- выключен: фильтр сервисного UUID Phoenix;
- включён: discovery всех доступных Android BLE advertisements, в том числе
  результатов без ScanRecord; это помогает отладке до появления своего advertiser;
- во время WAITING/SCANNING переключатель недоступен; выбранный режим применяется
  при следующем запуске. Повторный Start не сбрасывает активную сессию.

Android neverForLocation и ограничения платформы могут отфильтровать часть
advertisements даже в режиме всех устройств. Он не означает захват всего радиоэфира.

Добавлены отдельные статусы location disabled и unsupported BLE. Ошибки Android
показывают числовой код и пояснение. Время начала — время фактической попытки
startScan, а не нажатия кнопки. Время на экране отображается как дата/время
устройства вместо количества минут от Unix epoch. Внешний экран прокручивается,
внутренний список устройств сохраняет ограниченную высоту и собственную прокрутку.

Работа всё ещё останавливается в Activity.onStop; постоянного фонового сервиса,
автовозобновления, подключения по нажатию на устройство и передачи сообщений нет.

## Проверки

JVM-тесты с fake scanner/readiness/scheduler/clock проверяют весь путь сервиса:
синхронные callbacks, сохранение и объединение результатов, поздние callbacks,
повторные start/stop/close, отмену ожидающего старта, смену permissions, ошибки
cleanup и сохранение диагностик. Отдельно проверены ограниченный кэш, копирование
metadata, UI projection, коды Android и permissions разных API.

Команды проверки:

```bash
bash gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Физические проверки: Android 10–11 с location off/on; Android 12+ с отзывом
Nearby Devices permissions; Bluetooth off/on; оба режима фильтра; быстрая
последовательность start/stop; уход в фон; поворот экрана; поздний callback;
advertiser с совпадающим/чужим UUID, изменяемым именем, txPower и manufacturer data.

Радио и поведение OEM нельзя подтвердить JVM-тестами. AndroidBleScanner остаётся
небольшой платформенной границей, которую необходимо проверить на устройствах.
